# Native load, soak and failover qualification

This lane supplies a real SDK workload driver and a private site-adapter protocol, with source-bound observations and strict budget checks. No native target, approved budget, physical host or 24-hour run exists in this delivery. NATIVE_RUN_PACKET.json is an explicit NotRun template. Local loopback mTLS tests use substituted SQL/cache resources and never qualify production performance.

Build tests/Treehammock.SessionValidation.QualificationBenchmark/Svs.Benchmark.csproj with .NET 10 from a directory outside the source global.json, restore --locked-mode --disable-parallel -m:1 -p:NuGetAudit=false, then build --no-restore -m:1. Test project tests/Treehammock.SessionValidation.QualificationTests/Svs.Qualification.Tests.csproj references the existing HostTests fixture via a test-assembly friend only. No production friend assembly or runtime injection surface is added. Run its executable with -xml ABSOLUTE_REPORT. Python negative checks use `python3 -m unittest discover -s eng/session-validation/qualification -p 'test_*.py'`.

The console driver accepts only --stdin; the private orchestrator sends camelCase JSON through a pipe. It never accepts a token on argv/environment. Input contains clients [{replica, options: ClientOptions}], vectors [{label, credential, action, expectedDecision, account, family, generation, protocol}], durationSeconds, concurrency, requestsPerSecond, requestLimit. ClientOptions is the existing private, pinned mTLS SDK configuration. Labels are the eight reviewed active/malformed/wrong-signature/revoked/forbidden/expired/refresh-race/logout-race names. ExpectedDecision is Active/Unauthenticated/Forbidden/Unavailable. Active requires the exact authoritative tuple oracle. JSON is closed, duplicate properties rejected, and raw input bytes are cleared; immutable .NET strings cannot be guaranteed zeroed. Use isolated private mounts and prevent debugger/core/swap capture according to the existing key runbook.

The SDK driver has 1..64 workers, up to eight replicas plus one VIP, 1..90000 seconds, 1..100000 requests/sec, and at most 100 million requests. No request queue or per-call retained sample list is allocated: workers pace directly from a monotonic schedule and exert backpressure. A fixed 65537-cell histogram reports conservative upper-bound quantiles at 64us resolution; overflow prevents budget acceptance. A 250ms sampler reports DRIVER CPU time, peak working set and FD count. Driver/core throughput is labeled as driver-only. Actual SERVER cores/CPU/pool/DB/fence/cache/lag figures must come from the separate site observer; they are never inferred from driver process metrics. The driver returns Completed or Cancelled with nativeQualified/grantRights/releaseReady always false, and owns/disposes all SDK connections.

`python3 qualification.py schedule` emits the complete pending 15-phase schedule. To execute, copy the example into a new private plan, replace every placeholder, independently approve budgets and isolated targets, and run `python3 qualification.py run --plan ABSOLUTE_PRIVATE_PLAN --output NEW_PRIVATE_DIRECTORY`. Linux inputs must be owned nonsymlink 0400/0600 files, including the benchmark DLL and reviewed Python site hook. Deploy the benchmark with its deps/runtimeconfig files beside it in a private directory; pin the DLL digest. The hook is invoked with Python, so the source file remains 0600 and need not be executable. Runtime location is an explicit absolute dotnet path; record its version/digest in the independent host inventory. All output is private 0600 in a new 0700 directory, and no raw subprocess stderr is exported. Core dumps are disabled; child output is capped at 1MiB; groups are terminated/killed on timeout/cancel. Ctrl-C/SIGTERM requests idempotent cleanup. SIGKILL or host loss requires the recovery procedure below.

The plan schema is the example's exact fields. Source and host/runtime/ACL inventory SHA256 digests bind every phase and observer. Replicas must be two to eight explicitly named physical targets (`svs-1` through `svs-8`); the native orchestrator requires this exact set in both client input and observer output. Client input is the benchmark clients array. Vector input is the benchmark vectors array with credential_file replacing credential; the file holds a synthetic staging credential. Every secret is loaded through a private file and piped, never logged. The example scope UNCONFIGURED and tiny budgets intentionally refuse actual qualification; they are not recommended SLOs.

The Python site hook receives one closed JSON operation via stdin: version=1, operation, phase (or null), run_id, scope=IsolatedStaging, source_sha256, inventory_sha256. It must independently verify that all infrastructure is disposable or explicitly owned isolated staging before acting. Preflight returns exactly {status:Prepared, run_id, inventory_sha256}. Begin returns {status:Begun, run_id, phase}; end returns {status:Ended, run_id, phase}; cleanup returns {status:Cleaned, run_id}. Observe returns the exact observer schema enforced by observer_check: version, phase, source_sha256, inventory_sha256, run_id, fault_verified, isolation_verified, credentials_only_synthetic, elapsed_seconds, proof_sha256 and servers keyed by exact replicas. The fixture-specific hook is deliberately not invented for unknown customer infrastructure. Review and pin its Python source before a run; use the existing disposable native lane for owned-container implementations where applicable.

Each server row contains cores, cpu_seconds, working_set_peak_bytes, file_descriptors_peak, sql_read_p99_us, pool_wait_p99_us, writer_fence_p99_us, revocation_lag_us, hit_requests, hit_sql, hit_control, hit_hint, fallback_sql_reads, publisher_writes, mutation_samples, mutation_false_active and writer_fence_samples. proof_sha256 identifies the independently retained private timestamped phase trace. Counts and finite metrics are bounded; unknown fields fail closed. Usable-hit SQL/control/hint counts must all be zero, unexpected decisions/tuple drift/false Active must be zero, and every replica must have minimum samples. Login/refresh/logout storm phases additionally require actual mutation and writer-fence witness samples. Native observer proof must establish commit-before-read ordering and revocation timing; an asserted Boolean is not a substitute for trace review.

The benchmark uses stable sentinel tuple/decision oracles. During login/refresh/logout storms, the site hook starts real writer workload and an independent linearization witness; the driver also probes already-revoked sentinels. Mutable tokens spanning a commit must be adjudicated against the witness, not compared blindly with a fixed expected Active. Record mutation_false_active and maximum revocation lag from that trace. Fail if a trace is absent or any post-commit Active occurs. The driver itself does not simulate a writer or mutate auth tables.

For a 24-hour qualification the soak requests 86460 seconds and the measured monotonic driver AND observer durations must each reach 86400 seconds. Hitting requestLimit early, cancellation or a partial run never qualifies. Set rate/limit to allow the full interval; 100 million calls may be too small for higher rates and must be split into source-bound consecutive runs under an explicitly reviewed extension before any claim. Record timestamps, gaps and source/host identity; do not add separate partial durations and call them an uninterrupted soak.

Every non-soak phase must reach its configured monotonic duration; an early request-limit exit is incomplete. Quantiles must be ordered and native trace digests cannot be placeholders. Every completed phase remains BudgetChecksPassedPendingIndependentReview and a complete run remains MeasuredUnqualified. Cleanup must be affirmatively verified. RUN_STATUS.json records partial/cleanup failures. No release/promotion flags are set, even with a locally passing observer. Independent signed attestation of actual native evidence, physical budgets, parity and all open findings is required. Differences between action-policy profiles remain a blocking subject until adjudicated.

## Drill and recovery packet

- cold-cache: initialize an isolated empty epoch using existing admission controls; capture fallback/refill pressure and validate bounded reads.
- hot-cache: warm through the SVS-owned refill path; prove hits use zero SQL/control/hint calls and expire conservatively during DB loss.
- mixed-refusals: wrong signature, malformed, revoked, expired and forbidden vectors; no returned identity on refusals.
- login-storm / refresh-race / logout-race: real TreeHammock writers with authoritative trace and full writer/global barrier coverage. Never inject direct auth SQL mutations as a substitute.
- ysql-leader-transfer: invoke the approved isolated-cluster management operation and record old/new leader identity and linearization; a container pause alone is not leader-transfer proof.
- cache-loss / refill-outage: remove only owned staged cache/refill paths; verify conservative fallback, pressure caps and no late refill resurrection.
- replica-loss / haproxy-failover: two real distinct SVS nodes, remove each backend in turn, then the owned proxy path; observe every serving replica and connection churn.
- tls-rotation: overlap then retire the old client/server pins with old-denied/new-accepted evidence; no insecure verification bypass.
- network-partition: prove old-primary reader AND publisher isolation before any replacement admission; require the complete signed peer inventory and all-peer barriers.
- recovery: drain requests and raw dependency ownership, reconcile, create a fresh empty epoch when required, then readmit through the existing workflow. No automatic stale follower promotion.
- soak-24h: continuous mixed traffic with immutable approved budget, periodic host/resource/counter trace, authorized failure drills and zero escalation; measure at least 24 real hours.

End must restore the phase fault and stop only its owned workload; global cleanup must be idempotent for run_id even after failed preflight. Keep an out-of-band record of run_id, owned IDs and hook digest. After SIGKILL/host loss, verify the hook hash and target ownership, invoke its cleanup operation with that exact run_id and retain its Cleaned receipt; otherwise leave CleanupUnverified. Do not delete or start unrelated infrastructure. Retain sanitized metrics and private evidence under the approved policy, destroy synthetic credentials and job keys, and never restore local JWT or provisional CBK JSON fallback. Local checks do not by themselves authorize or apply host, kernel, firewall or service configuration changes.
