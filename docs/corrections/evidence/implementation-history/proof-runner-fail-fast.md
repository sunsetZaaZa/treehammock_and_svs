# COR23Q — First failure stops proof runners

Date: 2026-10-09 (America/Chicago). Baseline: delivered COR23P. Finding: R10A-01. Implementation: FixedPendingQualification. Actual PowerShell parser/execution, compiled native fixture and application/service qualification: NotRun.

The current PowerShell runners relied on ErrorActionPreference Stop for external dotnet/Docker commands; several executed later stages after a nonzero process result. Nested proof scripts also lacked explicit result checks. Existing Python collector wrappers already captured child codes, but did not share a common application-only invocation boundary. Docker pull retries and the host teardown path could hide or replace the initiating failure.

All 28 entrypoints now share a dot-sourced command helper and explicit top-level runner exit. Native calls resolve Application commands, receive typed argv arrays, immediately capture LASTEXITCODE, reject missing/nonzero results and carry the native code/stage through exception chains. Profiles/PSNativeCommandUseErrorActionPreference do not define the result. Native stderr with zero exit remains output rather than a false failure. Nested scripts capture nonthrowing exits explicitly. Wrapper diagnostics use bounded stage/code, not raw exception/argv material.

Restore, build, unit/integration/SQL tests, lock generation/status, Python collectors, Docker daemon checks/pulls/build/Compose operations and release/all-lane nesting use the boundary. First failed pull stops; no retry converts the attempt into success. Existing host cleanup captures the primary error, independently attempts process stop/Compose down/environment restoration, and rethrows the original tagged failure. Readiness detects an already exited API process and carries its exit code. No database/package-lock change or migration/compatibility system is introduced.

Existing native source assertions were updated for the explicit argv syntax rather than weakening their lane argument requirements. Real behavioral testing is provided by `eng/test-powershell-runners.py`, which compiles a controlled package-free process fixture and uses the selected actual PowerShell parser/host. It covers every entrypoint and observed failure position in File/Command modes, plus a genuine package-free SDK compile failure, nesting, missing lock/executable, stdout/stderr, argv spaces, profile settings and primary-versus-cleanup failures. It reports Blocked when either runtime is absent. CI requires Windows PowerShell 5.1 and PowerShell 7 on Windows/Linux, including artifacts on failure. Supplemental source mutation and fixture-plumbing tests do not count as native execution.

See [POWERSHELL_RUNNER_CONTRACT.md](POWERSHELL_RUNNER_CONTRACT.md) for support matrix, command/result semantics and qualification limits. Frozen specifications and all other finding/gate states are preserved. Coverage, configuration alignment, image tags, Compose service prerequisites, resource identity/partial acquisition cleanup and host selection remain separately scoped followups. This PR does not close R10A-01 or any release gate without actual supported-host/native qualification.
